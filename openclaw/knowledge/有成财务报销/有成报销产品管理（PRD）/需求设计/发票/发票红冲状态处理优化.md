## 一、需求背景

当前系统在发票红冲处理方面存在以下问题。

### 1.1 已删除发票重新上传时无法感知最新红冲状态

用户上传发票并验真成功后，系统会保存验真记录。该发票被删除后再次上传时，系统直接使用历史验真结果，不再调用企享云接口。

如果发票在“删除—重新上传”期间发生红冲，系统无法及时识别，可能导致已经红冲的发票继续用于报销。

### 1.2 部分红冲发票被直接禁止报销

企享云发票查验接口可能返回正常、部分红冲、全部红冲、作废等状态。现有系统将部分红冲和全部红冲统一按不可用处理，直接禁止上传。

实际上，部分红冲发票未被红冲的剩余金额仍可用于报销，需要根据红票金额计算蓝字发票的剩余可用金额。

## 二、需求目标
1. 每日重新查验符合条件的已验真发票，及时识别发票是否发生红冲或作废。
2. 单据审批同意和出纳支付时，对存在红冲发票的单据进行明确提示。
3. 支持企业配置红冲通知人。已经关联报销单的发票被定时任务查验出红冲后，向指定人员发送消息。
4. 上传发票时区分正常、部分红冲、全部红冲和作废状态。
5. 部分红冲时，通过红票信息进行二次查验，计算蓝字发票剩余可用金额。
6. 统一发票汇总、费用同步、拆分、核销和税额明细等场景的可用金额口径。

## 三、需求一：定时查验及红冲提醒

### 3.1 企业级定时查验开关

配置位置：管理后台—企业查询—企业操作—OCR服务到期时间弹窗。

新增配置项：【定时查验已验真发票】。

![image.png](https://alidocs2.oss-cn-zhangjiakou.aliyuncs.com/res/AJdl659W2bx8yOke/img/62545a2d-5047-4f98-806e-7aa9bcbe75a8.png?Expires=1789461391&OSSAccessKeyId=LTAI5tKTjg4Kq1HCdBJ8qpSp&Signature=aXF862%2F4cLTscbxn4YxnXkpPI6w%3D "")

配置规则：
1. 使用勾选框，默认不勾选。
2. 勾选并保存后，该企业从下一次定时任务开始纳入定时查验。
3. 取消勾选并保存后，该企业不再执行定时查验，不修改已有发票状态。

### 3.2 报销侧红冲通知人配置

配置位置：全局设置—发票设置—其他设置。

新增配置项：【已报销发票被红冲通知】。

![image.png](https://alidocs2.oss-cn-zhangjiakou.aliyuncs.com/res/ybEnB5Nwb9xJMlP1/img/6862c7d5-2820-447b-bb40-029617ebd909.png?Expires=1789461391&OSSAccessKeyId=LTAI5tKTjg4Kq1HCdBJ8qpSp&Signature=3GGvTjx1yjljeBJ4bJp4SSjiRrs%3D "")

配置规则：
1. 系统选人组件，支持多选，无需支持部门、角色。
2. 此处“已报销发票”指已经关联任意单据的发票，不区分报销单处于草稿、审批中、审批完成或已支付状态。
3. 未配置通知人时，定时任务仍正常更新发票状态，但不发送系统消息。
4. 已配置人员后续离职、停用或失效时，该人员不再接收消息；
5. 管理后台勾选【定时查验已验真发票】后，才展示这个配置项：【已报销发票被红冲通知】

### 3.3 定时查验范围

发票同时满足以下基础条件时，才可进入定时查验候选范围：
1. 发票所属企业已开启【定时查验已验真发票】。
2. 发票已经验真成功。
3. 发票已经关联一张或多张单据。
4. 发票开票日期距任务执行日不超过3个月，含任务执行日当天。
5. 发票当前未被标记为“存在红冲”。
6. 发票当前未被标记为“作废”。

满足基础条件后，系统根据发票关联单据的最新状态归入以下任务：
1. 审批中任务：发票关联的任意单据仍处于审批中，包括待审批、审批流转中等尚未形成最终审批结果的状态。
2. 审批完成任务：发票关联的单据审批流程已经结束且审批结果为通过，包括待支付、部分支付、已支付及审批完成等状态。

如果同一发票关联多个单据，且单据分别处于审批中和审批完成状态，则按审批中任务处理，保证按最高时效要求查验。

**未关联单据的发票不进入本次定时查验任务**。



### 3.4 定时任务处理规则

#### 3.4.1 企业未开启定时查验

不执行定时查验，保持现有业务逻辑。

#### 3.4.2 企业已开启定时查验

**审批中任务**

审批中的单据对发票状态时效要求高，系统每天凌晨执行一次审批中任务。

处理规则：
1. 按企业、按批次查询满足基础条件且关联审批中单据的发票。
2. 同一发票当天最多成功查验一次。
3. 当天查验失败的发票按定时任务既有重试机制处理；全部重试失败后，等待次日任务再次查验。

#### 审批完成任务

审批完成后的发票无需每日查验，系统每10天查验一次，任务在满足周期条件后的当天凌晨执行。

处理规则：
1. 距离上次成功查验时间满10天后，发票进入审批完成任务。
2. 发票没有历史成功查验时间时，以单据审批完成时间作为周期起点；审批完成时间无法取得时，以发票与单据关联时间作为周期起点。
3. 同一发票在一个10天周期内最多成功查验一次。
4. 查验失败不更新最后成功查验时间，按既有重试机制处理；重试仍失败时，在下一次凌晨任务中继续补查，不重新等待10天。



**查验结果处理**

审批中任务和审批完成任务查验后 按以下规则处理结果。

如果接口返回正常或未红冲：
1. 保持发票正常状态。
2. 更新最后成功查验时间。
3. 不发送红冲通知。

如果接口返回部分红冲或全部红冲：
1. 业务状态统一标记为“存在红冲”。
2. 更新发票提示信息为【存在红冲，查验时间：【--】】。

单据详情中需要展示发票的红冲状态

![image.png](https://alidocs2.oss-cn-zhangjiakou.aliyuncs.com/res/AJdl659W2bx8yOke/img/d729aa6e-48a3-4516-8dec-cd5f91c1fefd.png?Expires=1789461391&OSSAccessKeyId=LTAI5tKTjg4Kq1HCdBJ8qpSp&Signature=RrMGX19RbSCd1p00Gef7i%2FDBGE0%3D "")


3. 进入通知流程。
4. 后续定时任务不再重复查验该发票。
5. 删除系统验真表中该发票对应的验真记录，保证该发票后续再次上传时重新调用企享云接口查验。

如果接口返回作废：
1. 将发票标记为“作废”。
2. 更新最后成功查验时间。
3. 后续定时任务不再重复查验该发票。
4. 本期不按红冲规则发送通知。

如果接口调用失败或返回结果无法识别：
1. 不修改发票当前状态和最后成功查验时间。



### 3.5 红冲通知内容与防重复规则

通知方式：系统消息。

通知标题：【单据存在红冲发票】。

通知文案：
> 发票【发票号码】已查验为红冲状态，当前关联单据【单号】，请及时核实并处理。   

处理规则：
1. 同一企业、同一发票、同一次红冲状态识别只生成一次业务通知事件。
2. 定时任务重跑、消息重试或接口重复返回时，不得重复生成相同通知。

### 3.6 审批同意及出纳支付提示

审批人点击【同意】或出纳点击【支付】时，检查单据关联发票的最新状态。

如果单据不存在红冲发票：

保持原有审批或支付逻辑。

如果单据存在一张或多张红冲发票：
1. 弹窗提示：【该单据存在红冲发票，请核实】。
2. 审批弹窗提供【取消】和【继续审批】按钮。
3. 点击【取消】时关闭提示弹窗，不关闭审批弹窗，不执行审批操作，；点击【继续审批】时按原流程提交审批。
4. 支付弹窗提供【取消】和【确认】按钮。
5. 点击【取消】时关闭弹窗，不执行支付；点击【确认】时按原流程提交支付。
6. 本提示属于风险提示，不阻断审批同意、驳回或支付操作。驳回操作保持原有逻辑，不弹出该提示。

## 四、需求二：根据红票信息计算部分红冲发票可用金额

### 4.1 使用接口

报销当前使用企享云发票查验接口：

[https://openapi.qixiangyun.com/api-66282957](https://openapi.qixiangyun.com/api-66282957)



### 4.2 首次查验蓝字发票

用户上传发票后，系统调用发票查验接口获取蓝字发票状态。

如果状态为正常或未红冲：
1. 允许正常上传。
2. 发票可用金额等于蓝字发票原金额。

如果状态为全部红冲：
1. 禁止上传或提交。
2. 提示：【该发票已全部红冲，无法报销】。

如果状态为作废：
1. 禁止上传或提交。
2. 提示：【该发票已作废，无法报销】。

如果状态为部分红冲：
1. 从本次蓝字发票查验结果中获取对应的红票信息。
2. 进入红票二次查验流程。

### 4.3 红票二次查验

系统从蓝字发票返回的红票信息中提取红字发票号码、发票代码及接口要求的其他查验要素，再次调用同一查验接口获取红字发票金额。

金额口径：
1. 蓝字发票原金额、红字发票金额和剩余可用金额均按价税合计口径计算。
2. 接口返回的红字发票金额为负数时，计算时取其绝对值。
3. 同一红字发票只计算一次。优先使用“发票代码＋发票号码”作为去重标识；全电发票没有发票代码时，使用“唯一发票号码＋发票类型”作为去重标识。

如果只存在一张红票：

蓝字发票剩余可用金额 = 蓝字发票原金额 − 红字发票金额绝对值。

如果存在多张红票：
1. 系统逐张查验并汇总全部有效红字发票金额。
2. 蓝字发票剩余可用金额 = 蓝字发票原金额 − 有效红字发票金额绝对值合计。

计算结果不得小于0。如果结果小于0，则将剩余可用金额置为0。

### 4.4 红票查验结果处理

#### 4.4.1 全部红票查验成功，且剩余可用金额大于0
1. 允许上传和提交。
2. 保存蓝字发票原金额、红冲金额合计和剩余可用金额。
3. 发票卡片上的金额和发票区域汇总金额均展示剩余可用金额。
4. 发票下方使用红色提示文案：
> 该发票已被部分红冲，原金额为XX元，红冲金额为XX元，剩余可用金额为XX元。   

![image.png](https://alidocs2.oss-cn-zhangjiakou.aliyuncs.com/res/ybEnB5Nwb9xJMlP1/img/4cf2424d-592e-4105-b405-749035b809ec.png?Expires=1789461391&OSSAccessKeyId=LTAI5tKTjg4Kq1HCdBJ8qpSp&Signature=gesIxDS5SyvPyn2G9urOGvJLX8E%3D "")

#### 4.4.2 全部红票查验成功，但剩余可用金额等于0
1. 将发票标记为不可用。
2. 禁止上传。
3. 提示：【该发票剩余可用金额为0，无法报销】。



#### 4.4.3 任意一张红票查验失败

只要存在一张红票查验失败，就不得使用已经成功获取的部分红票金额计算剩余可用金额。

本期按已确认的降级规则处理：
1. 允许发票上传和提交。
2. 剩余可用金额按蓝字发票原金额计算，不设置为0。
3. 不展示“上传失败”状态，不提供“重新获取”按钮。
4. 发票卡片上的金额和发票区域汇总金额均展示蓝字发票原金额。
5. 发票下方使用红色提示文案：
> 该发票存在部分红冲，红票金额获取失败，请重新上传。   
6. 保存红票查验失败状态和失败原因，便于后续排查。

![image.png](https://alidocs2.oss-cn-zhangjiakou.aliyuncs.com/res/ybEnB5Nwb9xJMlP1/img/a0538543-fa71-4dd7-bbaf-1175e2ab19c9.png?Expires=1789461391&OSSAccessKeyId=LTAI5tKTjg4Kq1HCdBJ8qpSp&Signature=C7WQbjt5I75R4J2mcLVEXNkS3No%3D "")

### 4.5 可用金额保存及更新

发票保存以下金额信息：
1. 蓝字发票原金额。
2. 已查验成功的红冲金额合计。
3. 当前剩余可用金额。
4. 可用金额计算状态，包括正常、计算成功、降级使用原金额和不可用。

同一张发票重新查验后：
1. 如果状态或红票金额发生变化，重新计算并覆盖当前剩余可用金额。
2. 不修改已经完成的历史报销、核销或付款记录。
3. 新增、编辑、拆分及核销操作均以最新剩余可用金额进行校验。

### 4.6 发票金额关联逻辑说明

#### 4.6.1 发票金额汇总

如果发票正常，则汇总蓝字发票原金额。

如果部分红冲且红票查验成功，则汇总蓝字发票剩余可用金额。

如果部分红冲但红票查验失败，则按降级规则汇总蓝字发票原金额。

#### 4.6.2 费用金额同步

用户选择同步发票金额时，系统同步该发票当前剩余可用金额。

#### 4.6.3 发票拆分

发票当前可拆分金额 = 剩余可用金额 − 已占用金额。

如果可拆分金额小于或等于0，则不得继续拆分。

#### 4.6.4 发票核销及开票组件

核销或使用金额不得超过发票当前剩余可用金额。前端校验通过后，后端必须再次校验最新剩余可用金额及已占用金额，避免并发操作导致超额使用。

#### 4.6.5 税率税额组件

当前接口仅能通过红票二次查验获得红票总金额，不能确定红票与蓝票明细之间的逐行对应关系，因此统一按比例调整蓝字发票明细。

计算规则：
1. 分摊比例 = 剩余可用金额 ÷ 蓝字发票原金额。
2. 各明细调整后金额 = 原明细金额 × 分摊比例。
3. 各明细调整后税额 = 原明细税额 × 分摊比例。
4. 税率保持不变。
5. 金额和税额按系统现有精度四舍五入，尾差归入最后一条明细，确保明细价税合计等于剩余可用金额。

示例：

蓝字发票原价税合计为1,000.00元，其中不含税金额884.96元、税额115.04元；红票价税合计为200.00元。

剩余可用金额为800.00元，分摊比例为80%。调整后不含税金额为707.97元，税额为92.03元，价税合计为800.00元。
