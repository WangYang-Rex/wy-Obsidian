## <span style="background-color: oklch(1 0 0);">**1\. 需求背景**</span>

### <span style="background-color: oklch(1 0 0);">**1.1 需求描述**</span>

<span style="background-color: oklch(1 0 0);">为邮件拉取发票的附件保存逻辑增加优先级控制能力，在"同一封邮件内的发票和行程单合并为一笔消费"开启时，同一发票的多格式附件（pdf、ofd、xml）按 pdf \> ofd \> xml 优先级保存一份到消费中，提升用户查看发票附件的体验。</span>

### <span style="background-color: oklch(1 0 0);">**1.2 需求背景**</span>
- <span style="background-color: oklch(1 0 0);">需求方：使用邮件拉取发票的企业员工及财务管理员</span>
- <span style="background-color: oklch(1 0 0);">现状问题：</span>
    - <span style="background-color: oklch(1 0 0);">系统从邮件中获取发票附件时，同一张发票可能包含pdf、ofd、xml三种格式文件</span>
    - <span style="background-color: oklch(1 0 0);">开启"同一封邮件内的发票和行程单合并为一笔消费"后，这三个格式文件的发票仅会合并到一个消费中，且仅保存一个格式的发票文件</span>
    - <span style="background-color: oklch(1 0 0);">当前保存的是xml格式附件，不便于用户直接查看发票票面信息</span>
- <span style="background-color: oklch(1 0 0);">解决思路：</span>
    - <span style="background-color: oklch(1 0 0);">在附件保存阶段引入优先级判断规则：pdf \> ofd \> xml</span>
    - <span style="background-color: oklch(1 0 0);">合并消费模式下仅保存优先级最高的一份发票附件</span>

<span style="background-color: oklch(1 0 0);">业务流程</span>
```
系统从邮件拉取发票附件
    ↓
识别同一发票关联的多个格式文件（pdf、ofd、xml）
    ↓
判断"发票和行程单合并为一笔消费"开关状态
    ↓
若开启：按 pdf > ofd > xml 优先级保存一份附件到消费中
若关闭：各格式附件分别生成独立消费并各自存储
    ↓
员工在消费详情页查看已保存的附件
```

<span style="background-color: oklch(1 0 0);">功能位置：邮箱绑定-发票自动生成消费（全局设置-费用设置-同一封邮件内的发票和行程单合并为一笔消费）</span>

<span style="background-color: oklch(1 0 0);">现有能力：</span>

- <span style="background-color: oklch(1 0 0);">支持"同一封邮件内的发票和行程单合并为一笔消费"开关配置</span>
- <span style="background-color: oklch(1 0 0);">开启合并后，同一发票的三个格式文件（pdf、ofd、xml）仅会合并到一个消费中</span>

<span style="background-color: oklch(1 0 0);">缺失能力：</span>
- <span style="background-color: oklch(1 0 0);">不支持按 pdf \> ofd \> xml 优先级选择保存的发票附件格式</span>

### <span style="background-color: oklch(1 0 0);">**3.2 详细功能描述**</span>

#### <span style="background-color: oklch(1 0 0);">3.2.1 邮件发票附件保存优先级优化</span>

<span style="background-color: oklch(1 0 0);">位置：邮件拉取发票服务 → 附件解析与保存逻辑</span>

<span style="background-color: oklch(1 0 0);">新增配置/规则</span>
- <span style="background-color: oklch(1 0 0);">系统从邮件中解析同一发票的多个格式附件（pdf、ofd、xml）时，新增优先级判断规则</span>
- <span style="background-color: oklch(1 0 0);">优先级顺序固定为：pdf \> ofd \> xml</span>

<span style="background-color: oklch(1 0 0);">交互规则</span>
- <span style="background-color: oklch(1 0 0);">仅在"同一封邮件内的发票和行程单合并为一笔消费"开关开启时生效</span>
- <span style="background-color: oklch(1 0 0);">开关关闭时，保持现有逻辑不变</span>
- <span style="background-color: oklch(1 0 0);">若同一发票仅存在一种格式附件，则直接保存该格式</span>

<span style="background-color: oklch(1 0 0);">核心逻辑说明</span>
- <span style="background-color: oklch(1 0 0);">系统从邮件中拉取发票附件后，识别同一发票关联的多个格式文件</span>
- <span style="background-color: oklch(1 0 0);">判断合并开关状态：</span>
    - <span style="background-color: oklch(1 0 0);">开启：按优先级选取最高的一份附件关联到生成的消费中</span>
    - <span style="background-color: oklch(1 0 0);">关闭：各格式附件分别生成独立消费并各自存储</span>

<span style="background-color: oklch(1 0 0);">业务流程</span>
```
系统从邮件拉取发票附件
    ↓
识别同一发票的多个格式文件
    ↓
判断合并开关状态
    ├─ 开启 → 按 pdf > ofd > xml 保存一份 → 生成消费
    └─ 关闭 → 各格式分别生成独立消费
    ↓
消费详情页展示已保存附件
```

#### <span style="background-color: oklch(1 0 0);">3.2.2 消费详情附件展示</span>

<span style="background-color: oklch(1 0 0);">位置：我的-待办-消费详情页</span>

<span style="background-color: oklch(1 0 0);">核心原则：消费详情页直接展示该消费下已保存的发票附件，展示层不做额外的优先级筛选。</span>

<span style="background-color: oklch(1 0 0);">展示规则</span>
- <span style="background-color: oklch(1 0 0);">新拉取生成的消费：详情页展示按优先级保存的那份附件</span>
- <span style="background-color: oklch(1 0 0);">存量消费：详情页仍展示已保存的附件（如存量为xml则继续展示xml）</span>
- <span style="background-color: oklch(1 0 0);">若消费下无附件，展示区域保持为空</span>

## <span style="background-color: oklch(1 0 0);">**附录**</span>

<span style="background-color: oklch(1 0 0);">A. 典型使用场景</span>

<span style="background-color: oklch(1 0 0);">场景：企业员工通过邮件拉取发票后查看消费</span>

<span style="background-color: oklch(1 0 0);">配置状态（管理员已配置）：</span>
- <span style="background-color: oklch(1 0 0);">"同一封邮件内的发票和行程单合并为一笔消费"开关已开启</span>

<span style="background-color: oklch(1 0 0);">使用步骤（员工）：</span>
1. <span style="background-color: oklch(1 0 0);">员工邮箱收到一张包含pdf、ofd、xml三种格式的发票邮件</span>
2. <span style="background-color: oklch(1 0 0);">系统自动拉取邮件中的发票附件</span>
3. <span style="background-color: oklch(1 0 0);">系统按 pdf \> ofd \> xml 优先级，仅将pdf格式附件保存到生成的消费中</span>
4. <span style="background-color: oklch(1 0 0);">员工进入【我的-待办-消费详情页】查看该消费</span>
5. <span style="background-color: oklch(1 0 0);">消费详情中直接展示pdf格式发票附件，员工可清晰查看发票票面信息</span>

<span style="background-color: oklch(1 0 0);">结果：员工无需再打开xml格式文件，发票查看体验提升。</span>
