# **1\. 需求背景**

根据单据类型进行凭证分录合并的同时，需要判断费用类型，不是完全根据科目一致就合并，而是科目一致同时费用类型也一致，才能合并

# **2\. 业务流程/架构**

# **3\. 功能清单**

|------|---------|------|
| 会计科目映射 | 凭证分录合并 |  |
|  |  |  |

# **4\. 需求详情**

### **4.1费用类型判断**

在基础设置--会计科目映射--基础设置--凭证分录合并板块。新增一个开关“费用类型合并”

![image.png](https://alidocs2.oss-cn-zhangjiakou.aliyuncs.com/res/3M0Ozeyoj6LRZqze/img/e496742f-3c50-4e82-9884-8b6fe98cd653.png?Expires=1787120090&OSSAccessKeyId=LTAI5tKTjg4Kq1HCdBJ8qpSp&Signature=PiQmflyliv3na6X7tDPv7YAqCjA%3D "")
1. 默认开关关闭，此时合并与否还是仅按照单据逻辑来处理
2. 开关开启后，在进行分录合并时，需要先按照单据的合并逻辑来处理，同时多一层校验，待合并的单据的凭证分录其中费用类型是否一致，若一致才会合并，不一致则不会合并

![image.png](https://alidocs2.oss-cn-zhangjiakou.aliyuncs.com/res/3M0Ozeyoj6LRZqze/img/501cd26e-77b8-4729-bbc7-80f5e68ff93b.png?Expires=1787120090&OSSAccessKeyId=LTAI5tKTjg4Kq1HCdBJ8qpSp&Signature=V1GcJaDhoRThk17EgTDDpmnIVqY%3D "")

![image.png](https://alidocs2.oss-cn-zhangjiakou.aliyuncs.com/res/3M0Ozeyoj6LRZqze/img/16d0ab00-37f2-4810-8b71-1230c803a9d8.png?Expires=1787120090&OSSAccessKeyId=LTAI5tKTjg4Kq1HCdBJ8qpSp&Signature=Djuhbwyo0m%2FpZzdw5hV%2FNerSMvk%3D "")

![image.png](https://alidocs2.oss-cn-zhangjiakou.aliyuncs.com/res/3M0Ozeyoj6LRZqze/img/36ed67be-b9df-4fa2-9b1f-c48b9d7fd702.png?Expires=1787120090&OSSAccessKeyId=LTAI5tKTjg4Kq1HCdBJ8qpSp&Signature=qxyw2ryfTq2KjBy8B97wM41i03Y%3D "")
- **自动合并\+费用类型合并：借贷双方都需要根据费用类型进行合并判断**
    - 付款单贷方分录合并：仅对贷方分录根据费用类型合并，借方无需合并
    - 收款单借方分录合并：仅对借方分录根据费用类型合并，贷方无需合并
- **单个单据凭证分录合并\+费用类型合并****：**
    - 记-1合并后会存在四条分录。两个打车的生成一条借方金额33的分录；两个住宿的生成一条借方金额77的分录，还有库存现金的贷方金额33的分录和库存现金的贷方金额77的分录
    - 记-2合并后存在四条分录。由于两个费用明细类型不一致，所以相当于并未完成合并
- **多张单据合并生成凭证\+费用类型合并：**
    - 由于两笔都是付款单，所以会合并成一个凭证。分录存在四条。三个打车的生成一条借方金额为48的分录；三个住宿的生成一条借方金额为102的分录；还有一条库存现金的贷方金额48的分录和一条库存现金的贷方金额102的分录
- **自动合并\+单个单据/多张单据合并\+费用类型合并**
    - 同多张单据合并生成凭证\+费用类型合并的情况同理
3. 开关规则间无强绑定关系，可随意单独开启关闭配置。只不过如果只开启了“费用类型合并”并未配置合并规则，则这个开启规则相当于没用
4. 该配置仅影响增量凭证，历史凭证不做调整



注：确认目前凭证分录数据结构中是否缺少费用类型字段，如果缺少需要补充。
