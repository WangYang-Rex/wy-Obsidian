# **一、需求背景**

当前审批操作弹窗可能展示过多的后续节点，且未准确区分系统选人和当前处理人选人的场景。

需要统一审批、出纳、签收操作弹窗的后续节点展示范围和选人方式。

## 二、展示逻辑规则

审批、出纳或签收节点打开操作弹窗后，从当前节点的后一节点开始，按照流程顺序查找并展示后续节点。

审批、出纳、签收属于实际处理节点。

弹窗的后续节点展示范围为：
```
中间连续的抄送/AI节点
+
第一个审批、出纳或签收节点
```

如果后续没有审批、出纳或签收节点，则展示流程结束前的全部抄送节点和AI节点。



## 三、具体场景

### 场景一：后一节点是审批、出纳或签收节点（目前已实现逻辑）

示例：
```
审批A
→ 审批B（当前审批人选人）
→ 签收C
```

审批A的弹窗展示：
```
审批B：[请选择审批人]，可编辑
```

到审批B后停止，不展示签收C。

如果审批B的人员已经由系统确定，审批A的弹窗展示：
```
审批B：人员1，只读
```

即使审批B不需要当前审批人选人，也要在审批B处停止，不展示签收C。

### 场景二：后一节点是结束节点（目前已实现逻辑）

示例：
```
审批A
→ 结束
```

审批A的弹窗不展示后续节点和人员选择区域。

审批A处理完成后，流程结束。

### 场景三：经过抄送/AI节点后进入实际处理节点

示例一：
```
审批A
→ 抄送B（系统选人）
→ 抄送C（系统选人）
→ 审批D（当前审批人选人）
```

审批A的弹窗展示：
```
抄送B：人员1，只读
抄送C：人员2，只读
审批D：[请选择审批人]，可编辑
```

到审批D后停止。

如果审批D后面还有其他抄送、AI、审批、出纳或签收节点，均不在审批A的弹窗中展示。

### 场景四：后续全部是抄送节点或AI节点

示例：
```
审批A
→ 抄送B（系统选人）
→ AI节点C
→ 抄送D（当前审批人选人）
→ AI节点E
→ 结束
```

审批A的弹窗展示：
```
抄送B：人员1，只读
AI节点C：按AI节点现有方式展示
抄送D：[请选择抄送人]，可编辑
AI节点E：按AI节点现有方式展示
```

由于后续没有审批、出纳或签收节点，因此展示流程结束前的全部抄送节点和AI节点。

查找到结束节点后停止，结束节点本身不展示。

### 场景五：后续存在并行分支

当前节点后存在并行分支时，每条分支分别按照后续节点展示规则进行查找。

每条分支的展示范围为：
```
该分支中连续的抄送/AI节点
+
该分支中的第一个审批、出纳或签收节点
```

处理规则：
- 每条分支独立查找和停止，不能因为一条分支已经找到实际处理节点，就停止其他分支的查找。
- 每条分支遇到第一个审批、出纳或签收节点后，该分支停止继续向后查找。
- 所有分支查找完成后，将各分支需要展示的节点同时展示在当前弹窗中。
- 同时存在多个审批、出纳或签收节点时，需要全部展示。
- 需要当前处理人选人的节点展示可编辑选择框。
- 已经由系统或流程规则确定人员的节点只读展示。
- 某条分支后续全部为抄送或AI节点时，展示该分支结束前的全部抄送和AI节点。
- 某条分支直接进入结束节点时，该分支不展示后续节点。

示例：
```
审批A
├─ 分支一
│  → 抄送B（系统选人）
│  → 审批C（当前审批人选人）
│  → 签收D
│
└─ 分支二
   → AI节点E
   → 审批F（当前审批人选人）
   → 审批G
```

审批A的弹窗展示：
```
分支一
抄送B：人员1，只读
审批C：[请选择审批人]，可编辑

分支二
AI节点E：按AI节点现有方式展示
审批F：[请选择审批人]，可编辑
```

分支一查找到审批C后停止，不展示签收D。

分支二查找到审批F后停止，不展示审批G。

审批C和审批F属于不同并行分支中的第一个实际处理节点，因此需要在审批A的弹窗中同时展示。

审批A提交时，需要同时校验审批C和审批F的人员选择结果。任一必填节点未完成选人时，不允许提交。

为避免多个分支的节点混在一起，弹窗应按照分支分组展示。流程已经配置分支名称时展示实际分支名称；未配置分支名称时，可以按照流程顺序展示为“分支一”“分支二”。

## 四、提交规则

当前弹窗只校验本次展示范围内需要当前处理人手动选人的节点。
- 任一必填节点未完成人员选择时，不允许提交。
- 系统选人、申请人已选、固定人员等只读节点不执行手动选人校验。
- AI节点不执行手动选人校验。
